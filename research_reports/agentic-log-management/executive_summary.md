## 核心发现

### 三大技术路线

| 技术路线 | Token 节省 | 核心机制 | 适用场景 |
|---------|-----------|---------|---------|
| **LogSieve** | 40% | 语义保留精简 | CI 日志分析 |
| **CelerLog** | 80-94% | 动态路由(密集/稀疏分类) | 实时大规模 |
| **模板缓存**(LILAC/LogBatcher) | 显著 | 重复模式缓存 | 批量处理 |

### 关键技术洞察

1. **日志分类是核心**: CelerLog 通过区分密集型(80-90%)和稀疏型(10-20%)日志,实现 80-94% token 节省
2. **缓存命中率决定效率**: 日志通常有 70-90% 重复,模板缓存可显著减少 LLM 调用
3. **混合处理模式最优**: 实时(CelerLog)+ 批量(LogBatcher)+ 分析(LogSieve)
4. **语义保留 vs Token 节省需权衡**: LogSieve 保留完整语义(0.93相似度),CelerLog 牺牲部分语义换取更大节省

## 推荐架构方案

### 分层处理架构

```
日志输入
    ↓
[统计层] 密集型日志 → 正则/模板匹配(无需LLM)
    ↓
[缓存层] 重复模式 → 缓存命中直接返回
    ↓
[LLM层] 稀疏型日志 → 语义推理
```

**预期效果**:
- Token 节省: 70-90%
- LLM 调用减少: 80-90%
- 支持实时 + 批量双模式
